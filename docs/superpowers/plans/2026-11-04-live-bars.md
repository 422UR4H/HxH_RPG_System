# Live Bars, Projected per Recipient — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The master sees every character's bar move the instant an action is sent; players see bars move only as the master opens actions; no pending action or unopened die leaks to players.

**Architecture:** The domain computes one bars *view* per kind of recipient (`MatchSession.BarsView(isMaster)`), built on a scheduler projection that now uses a provisional price before the first open and reports pending/deferred speeds. The room sends `bars_updated` per recipient (direct lane) instead of broadcasting. The front renders the richer payload and hides what players no longer receive.

**Tech Stack:** Go 1.23 (stdlib `testing`), gorilla WS room; React 19 + TS strict + styled-components + Vitest.

**Spec:** `System_X_System/docs/superpowers/specs/2026-11-04-live-bars-design.md` (PT-BR: `.pt-br.md`). Read it first — decisions D1–D7, findings F1–F9, the wire table, and "Settled after the builder check".

- Back keeps exact fractional math; rounding is display-only, one decimal, via the front's existing `fmt` (`barsMath.ts`).
- The bar economy (mean, price, gates, carry, ceiling) does not change. The ECONOMY uses every recorded speed; only the projection to players filters.

## Review Focus

1. **Reconnect leaks.** A player reconnecting mid-round gets `match_full_state.bars` — it must be the player view (no `pending*`, no `deferred*`, no `provisionalPrices`, `order: []`). Test in Task 5.
2. **Cancelling the only pending action on a bar.** Provisional price for that bar disappears; the master's row falls back to carry, no meter. Test in Task 4.
3. **Combined action (move + attack).** Pending (or deferred) on BOTH bars at once, never split. Test in Task 3.
4. **A reaction's speed after the round closes.** Secret marks must not survive `ResetRound`, or the next round's player view drops a speed that is public. Test in Task 1.
5. **Player who also owns an NPC-like extra character / several characters.** Same player view for all of them; the player's OWN pending action leaves no trace in their bars. Test in Task 5.
